# 需求生命周期与研发安排（2026-09-28）

本说明为当前实现口径，替代旧《改版方案》中需求状态与人工流转的相关规则。

## 两个入口

- **需求提议**：记录尚待评估的想法与反馈。项目内产品、主开发、开发、测试均可提交，也可代录客户意见；分别记录提出人和实际录入账号。产品或系统管理员负责评估、确认采纳。
- **需求池**：只管理已经决定开发的需求。来自提议确认，或由产品、系统管理员直接创建；初始均为“已确定”，背景与目标、验收标准必填。已确定表示决定开发，不等于任务范围、排期已经准备好。

提议状态：待评估、评估中、待补充、暂缓、不采纳、已转需求。待补充、暂缓、不采纳需写明评估原因。提出人可修改本人待评估、待补充的提议；补充后回到待评估。已转需求的提议保留评估记录和关联入口，后续修改在需求中进行；重复确认不会重复创建需求。

## 内容与文档关联

提议与需求的区别是业务是否已经确认开发，内容结构和文档关联能力一致。未确认提议也可填写完整背景、方案和验收标准，关联项目内已有文档全文、具体章节及验收用例，不必等到进入需求池才补资料。

确认转入时沿用文档引用，不复制文档或生成额外文档版本；旧需求原位确认仍保留编号、任务、附件和文档关联。后续需求修改不回写已经转出的提议评估记录。

项目文档按未归档的实际关联自动显示“已确认需求、未确认需求、未关联”分类。一个文档可以同时关联两类业务并显示两个标签；转出的提议不再重复计数。分类反映关联业务的确认状态，与文档类型、版本或文档自身是否定稿无关。

## 在研发任务中安排工作

进入项目的“研发任务”，按需求分组查看和安排：主开发或系统管理员在“研发设置”中指定主责开发、维护前置需求；再拆分任务、分派负责人、填写预估工时和任务起止日期。主责开发可以是主开发本人，也可以是项目内其他开发成员。开发可在自己参与的需求下为自己补充任务。

保存这些实际安排后，系统立即检查关联条件并同步需求阶段。没有额外的“提交研发计划”或“启用自动流转”步骤，也不需要在需求编辑表单中逐级选择执行状态。

## 交付流程

| 阶段或操作 | 触发与条件 |
| --- | --- |
| 已确定 | 需求已决定开发，但主责开发、任务拆分、负责人或工时等准备尚未齐全。 |
| 待排期 | 已指定主责开发，有验收标准和至少一项有效任务，每项任务都有负责人及大于零的工时，但任务日期尚未全部齐全。 |
| 已排期 | 上述准备完成，且每项有效任务都有合法的开始和截止日期，系统自动进入；所有内容一次填齐时可直接由已确定进入。需求承诺日期不是任务排期的替代品。 |
| 开发中 | 首次开工须满足拆分、任务日期和前置依赖条件；首个任务开始开发后，需求自动进入开发中。 |
| 测试中 | 所有有效任务均已提测或完成，且验收标准已填写时自动进入。新增未完成任务或任务返工时同步退回开发中。 |
| 已完成 | 有效任务全部完成后，产品、主开发、测试或系统管理员对照整体验收标准人工确认。 |

有效任务不包含已删除、归档或终止的任务；零有效任务不会视为完成。任务新增、修改、转移、终止、归档或恢复，以及需求研发设置等相关变更，会重新检查条件。开始研发前，缺项变化可使已排期回到待排期或已确定；已经开始的研发保留执行阶段，同时提示资料或排期缺项。

日期到达只用于提醒与风险判断，不会自动开工或验收。所有任务完成后需求仍处于测试中，显示等待需求验收；人工确认后才进入已完成。

## 研发区间与交付承诺

- 研发开始、研发截止分别汇总有效任务中最早的开始日期和最晚的截止日期。部分任务未排期时可以显示已知边界，但会明确提示缺少日期的任务数量，不把局部日期当作全部排期完成。
- 需求中的承诺开始、承诺截止和基线保持独立。修改任务日期不会覆盖承诺，也不会自动改写基线；调整承诺须由有权限的人明确保存并保留记录。
- 需求列表、详情和工作台同时区分研发日期与承诺日期。全局甘特主条优先展示任务汇总的研发周期，承诺区间和基线作为独立参照。
- 风险区分承诺已经逾期、研发区间已经逾期、任务预计晚于承诺。尚未到期的预测偏差不会被写成已发生的承诺逾期。
- 主开发的“待我安排的需求”根据实际缺项提示拆分或排期，点击直接进入对应研发任务分组；条件补齐后自动从清单中移除。

## 异常处理与留痕

- 测试中可退回整改，须说明原因并选择返工任务，需求与所选任务一起退回开发中。
- 产品或系统管理员可终止需求，须说明原因。终止后自动流转停止。
- 已完成需求由产品、主开发、测试或系统管理员重新打开；已终止需求由产品、主开发或系统管理员重新打开，均须说明原因。已完成需求重开后保留待返工标记，须重开任务或补充返工任务，避免因上一轮任务都已完成而立即跳回测试中；无需重新提交计划。
- 已完成、已终止的需求须先重开，再调整任务范围、负责人、日期或执行状态。
- 需求和任务详情保留修改前后值、操作人、时间及原因。自动流转还记录触发任务，便于追溯。
- 删除任务仅系统管理员可操作，采用可恢复归档，历史记录保留。

## 旧数据兼容

数据库第 5 版新增提议表，不重写原业务数据。旧“未确定、待评审”需求在提议模块评估，确认时沿用原需求编号，保留任务、文档、附件与历史。未确认前不能新增、移入或推进研发任务。

原有已确认需求仅在打开或刷新页面时保留原状态，不批量改写历史。首次相关业务写入（如保存研发设置、修改需求、拆分或更新关联任务）后，自动采用任务驱动规则并记录实际变化；无需手动启用。新建或提议转入的需求直接使用新规则。

历史任务已经开工但日期等资料不完整时，可以继续提测与验收，界面仍提示待补缺项；新开工和重新开始开发继续校验适用条件及前置依赖。历史需求尚无任务日期时，全局甘特可以保留承诺窗口供参考，并标注“历史承诺区间（非任务汇总）”，不会伪造任务日期或覆盖承诺。
