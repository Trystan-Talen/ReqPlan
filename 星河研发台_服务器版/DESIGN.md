# 星引研发台 · 设计系统（夜航）

本文件是界面设计的**唯一规范**。任何人或 agent 新增页面、模块、组件，或修改现有界面前，都必须先读完「三条硬规则」和「新增页面步骤」。
样例页面：启动服务后打开 `/design-system.html`（无需登录），所有样例都由真实组件渲染。

## 1. 三条硬规则（有自动测试把关）

| 规则 | 要求 | 由谁检查 |
| --- | --- | --- |
| **只用令牌** | 颜色只能出现在 `frontend/design/tokens.css`。其他 CSS、JS 模板里不写 `#hex`、`rgb()`、`hsl()`；内联 `style` 只允许几何量（`left/right/top/width/height/flex`）和 CSS 自定义属性（`--xxx`）。 | `backend/tests/design-system.test.mjs` |
| **先用组件** | 按钮、状态标签、优先级、头像、页头、指标、面板、空状态、提示、表单字段一律调用 `frontend/ui-kit.js`。模板里出现的每个类名都必须有样式定义。 | 同上 + 代码评审 |
| **按模式搭页面** | 页面骨架只用第 5 节的模式：页头 → 指标条（可选）→ 面板。详情和编辑用右侧抽屉，确认用居中弹窗，预览用宽弹窗。 | 代码评审 + 样式指南对照 |

`npm test` 失败信息会指出违规的文件、行号和修复方向。**不要为了让测试通过而修改测试的判定条件**；确需新增结构钩子类时，登记到测试中的 `HOOK_CLASSES` 并写明原因。

## 2. 文件地图

```text
frontend/
├── design/                     样式，按层级加载，顺序不可调换
│   ├── tokens.css              ① 设计令牌：颜色、字号、间距、圆角、阴影、动效、层级
│   ├── base.css                ② 元素重置、工具类、共享动画、品牌标志
│   ├── components.css          ③ 跨页面组件（按钮、表单、标签、头像、面板、表格、弹窗…）
│   ├── layout.css              ④ 应用外壳（侧栏、顶栏、内容区）与登录页
│   └── pages/                  ⑤ 页面专属样式，一个页面（或一组紧密相关页面）一个文件
│       ├── dashboard.css       团队工作台、项目目录、项目概览
│       ├── tasks.css           按需求组织任务、研发任务看板
│       ├── requirements.css    需求提议、需求交付阶段与流转条件
│       ├── members.css         项目成员、账号管理
│       ├── work.css            我的工作、站内提醒、交付报表
│       ├── timeline.css        交付排期（甘特图）；坐标轴、网格与缩放控件也用于全局排期
│       ├── portfolio.css       全局排期（项目概况表、跨项目甘特图、按人员泳道）
│       ├── document.css        附件文档预览、提议与需求共用文档关联选择器
│       ├── documents.css       项目文档、章节阅读与需求关联
│       └── styleguide.css      样式指南页面自身的排版
├── ui-kit.js                   组件生成函数（纯函数，返回 HTML 字符串）
├── design-system.html/.js      活样式指南
├── index.html                  应用入口；引入全部样式层
└── app.js / work-ui.js / timeline.js / portfolio.js / …   视图与交互
```

样式层的职责边界：

- **tokens** 只定义变量，不写选择器规则（深色主题重定义除外）。
- **base** 只写元素选择器、工具类（`.muted`、`.sr-only`…）和 `@keyframes`。
- **components** 写可在两个以上页面复用的组件。一个组件只在一个页面用到时，放到对应的 `pages/*.css`。
- **layout** 只管外壳。页面内容渲染进 `#view`，新页面**不需要**修改 layout。
- **pages** 只写该页面特有的结构；不得重新定义组件的外观（例如不要在页面里改 `.btn` 的颜色）。

## 3. 设计原则

1. **明暗对比出辨识度**：深墨色侧栏（夜色区域）+ 暖白纸面画布。品牌渐变只出现在标志、登录页和首页横幅，不要扩散到业务组件。
2. **一个强调色**：主按钮是墨色（`--ink`），强调色「星引靛蓝」（`--accent`）只用于焦点、选中、链接和进度。浅色主题使用主色，深色主题使用同色系浅靛；标志使用固定的 `--brand-primary`。保留原暖灰纸面与墨黑框架，不把品牌色替换为任务状态色或项目识别色。
3. **状态用色点，不用大色块**：状态标签是「小圆点 + 浅底 + 同色文字」；大面积彩色只用于数据可视化（甘特条、进度环）。
4. **数字要对齐**：指标、日期、工时、编号使用等宽数字；编号使用 `--font-mono`。
5. **信息密度适中**：列表行高约 48px，面板内边距 16–20px，页面区块间距 18px。宁可分面板，不要堆砌分割线。
6. **上下文不丢失**：看详情、编辑都从右侧抽屉打开，背后列表保持可见。
7. **项目与全局各有边界**：团队工作台聚焦可访问项目的推进、风险与个人职责内的待办；项目目录负责查找、比较和进入项目；全局排期负责跨项目协调。单项目详情、需求与研发任务仍在项目导航下。工作台保留原欢迎区、四指标、主栏与侧栏骨架，不改变业务数据。任务完成数量只表示有效任务的状态，不等于需求验收或项目交付。
8. **小星适度出现**：品牌角色「小星」只用于团队工作台欢迎横幅，保留紧凑高度与向上破边的构图，不挤占操作区域。风险、验收结果和业务空状态由真实数据及标准组件表达，不让角色替代状态、按钮或统计信息。

## 4. 令牌

### 4.1 颜色

| 令牌 | 用途 |
| --- | --- |
| `--bg` / `--bg-grain` | 页面画布（外壳背景） |
| `--surface` | 面板、卡片、输入框、抽屉背景 |
| `--surface-2` | 表头、面板备注、次级区块 |
| `--surface-3` | 分段控件底、计数胶囊、空状态图标底 |
| `--surface-hover` | 行、列表项悬停 |
| `--border` / `--border-strong` | 默认边框 / 悬停或强调边框 |
| `--text` / `--text-2` / `--text-3` | 主文字 / 次要文字 / 辅助说明与占位 |
| `--ink` / `--ink-text` | 主按钮底色与文字（深色主题下自动反转） |
| `--accent` / `--accent-strong` / `--accent-soft` / `--accent-ring` | 链接与焦点 / 悬停 / 选中浅底 / 聚焦光圈 |
| `--brand-primary` / `--brand-on-dark` | 固定品牌主色（标志）/ 深色背景上的浅靛强调；不随主题切换 |
| `--c-{slate,violet,blue,amber,green,gray,red,orange}` + `-bg` | 语义色调，**状态标签、提醒、风险的唯一颜色来源** |
| `--shadow-{xs,sm,md,lg}` | 层级阴影：静止卡片 sm，悬停 md，抽屉与弹窗 lg |
| `--sidebar*` | 侧栏（夜色区域） |
| `--sidebar-active` / `--sidebar-active-border` / `--sidebar-active-rail` / `--sidebar-active-icon` / `--sidebar-active-text` | 导航选中的柔和靛蓝底、细边、浅靛左边条、图标与白字；全局和项目导航使用同一规则，选中与悬停明确区分 |
| `--night-*` / `--on-night-*` / `--brand-*` / `--glow-*` / `--starfield` | 夜色区域：侧栏、首页横幅、登录页左侧。**只能用在深色背景上** |
| `--hero-fill` / `--hero-border` / `--hero-secondary` / `--hero-accent` / `--mascot-shadow` | 团队欢迎横幅的背景、细边、次要文字、浅靛强调，以及小星阴影；不用于其他业务面板 |
| `--bar-*` | 甘特条颜色（与任务阶段一一对应） |
| `--project-1…6` / `--project-none` | 项目识别色，由 `projectColor(id)` 按项目顺序分配 |
| `--toast-*` / `--code-*` / `--backdrop` / `--preview-canvas` | 提示气泡、代码块、弹窗遮罩、原型预览画布 |

深色主题：`tokens.css` 里有两处深色定义（`:root[data-theme="dark"]` 和 `prefers-color-scheme: dark`），**必须同步修改**，测试会比对。夜色区域、数据色、项目色与主题无关，不要在深色块里重定义。

品牌基色为星引靛蓝；主色、悬停色、浅底及深底强调分别由 `--brand-primary`、`--accent-strong`、`--accent-soft`、`--brand-on-dark` 统一管理。深色主题的强调按钮使用深色文字 `--on-accent`，避免浅靛底配白字。品牌渐变和光晕限制在同一靛蓝色系；`--glow-cyan` 保留旧令牌名以兼容现有布局，其取值已属于品牌色系。

浏览器标签图标由 `brand-init.js` 复用 `BRAND_MARK` 图形，并读取固定品牌令牌生成数据图像；不在独立图标文件中维护第二套颜色，不改变主题存储与内容安全策略。

新增颜色的流程：①确认现有令牌确实无法表达 → ②在 `tokens.css` 对应分组加令牌（主题色需同时补两处深色值）→ ③在本表登记用途 → ④在 `design-system.js` 的色板里加样例。

### 4.2 状态色调（业务状态 → 视觉）

映射只在 `ui-kit.js` 的 `STATUS_TONES` 维护，对应 CSS 类 `.status-<tone>`。`workflow.js` 新增状态而未登记色调时，测试会失败。

| tone | 颜色 | 业务含义 | 状态 |
| --- | --- | --- | --- |
| `plan` | 灰蓝 | 已计划、尚未动工 | 待开始、已确定、待排期、已排期、规划中、暂缓 |
| `review` | 紫 | 需要讨论或确认 | 未确定、待评审、待评估 |
| `progress` | 蓝（带光圈） | 正在进行 | 开发中、进行中、评估中 |
| `test` | 琥珀 | 验证中 | 测试中 |
| `done` | 绿（对勾） | 完成、可用 | 已完成、已转需求、账号已启用 |
| `terminated` | 灰 | 终止、停用 | 已终止、不采纳、账号已禁用 |
| `pending` | 橙 | 等待他人动作 | 待补充、账号待激活 |
| `danger` | 红 | 风险 | 逾期等（用 `toneBadge('danger', …)`） |

逾期统一用红色文字 `.overdue-text`，或在卡片左侧加红边（`.task-card.is-overdue`）。不要把逾期做成整块红底。

### 4.3 排版

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--text-display` | 34px | 指标大数字、进度环数字 |
| `--text-3xl` | 30px | 页面标题 h1、首页问候 |
| `--text-2xl` | 21px | 抽屉内实体标题 |
| `--text-xl` | 17px | 分区标题 |
| `--text-lg` | 15px | 面板标题、弹窗标题 |
| `--text-md` | 14px | 正文（body 默认） |
| `--text-base` | 13.5px | 按钮、输入框、列表标题 |
| `--text-sm` | 12.5px | 次要正文、表单标签、小按钮 |
| `--text-xs` | 11.5px | 表头、元信息、计数 |
| `--text-2xs` | 10.5px | 甘特刻度副标 |

字重：正文 500，强调 560–600，标题 650–700。标题使用 `--font-display` 并带轻微负字距；编号、日期区间使用 `--font-mono`。

### 4.4 间距、圆角、动效、层级

- 间距 `--space-1…8` = 4 / 8 / 12 / 16 / 20 / 24 / 32 / 44px。间距令牌只用于 margin、padding、gap，**不要拿来当字号或圆角**。
- 布局节奏只有三档：`--gap-block` 18px（页面区块之间、并排栏之间）· `--gap-section` 12px（分区标题与内容）· `--gap-card` 14px（卡片网格）。
- 圆角：`--radius-xs` 6（小标签）· `--radius-sm` 8（小按钮）· 10px（按钮、输入框）· `--radius` 12（卡片内块）· `--radius-lg` 16（面板、卡片）· `--radius-xl` 22（首页横幅）· `--radius-pill`（胶囊）。
- 动效：`--duration-fast` 用于悬停，`--duration-base` 用于遮罩，`--duration-slow` 用于入场；缓动统一 `--ease`。页面入场动画用 `rise`，弹窗用 `drawer-in` / `pop-in`。已全局支持「减少动态效果」。
- 层级：`--z-sticky` < `--z-topbar` < `--z-sidebar-shade` < `--z-sidebar` < `--z-skip-link` < `--z-toast`。原生 `<dialog>` 处于顶层，不需要 z-index。

## 5. 页面模式

### 5.1 页面骨架

```js
function exampleView() {
  return heading('页面标题', '一句话说明这个页面帮用户做什么。', actionsHtml, '范围（项目名 / 团队空间 / 系统管理）')
    + readonly()                                   // 只读或受限权限时的说明（项目内页面）
    + metricStrip([...])                           // 可选：最多 4 个关键数字
    + panel({ title: '…', bodyHtml: … });          // 内容一律在面板里
}
```

- 在 `renderView()` 的路由表里注册视图，在 `renderShell()` 的导航里加入口（团队功能放 `main-nav`，项目功能放 `project-nav-links`，管理功能放 `admin-nav`）。
- 页面主操作放在 `heading()` 的 actions 中，**只放一个** `primary` 按钮，放在最右侧；次要操作用 `secondary`。
- 需要搜索时，在 `renderShell()` 的 `searchLabel` 映射中登记；页面内不要再放搜索框。

### 5.1a 区块间距与并排布局（有自动测试把关）

区块之间的距离**只由容器决定**，组件自己不带外边距：

- `#view` 是纵向栈（`display:flex; gap: var(--gap-block)`），页头、指标条、面板、网格直接放进去即可，不需要也不允许再写 `margin-top`。
- 需要并排时用布局原语：`.split`（主栏 + 侧栏，侧栏宽度用 `--aside` 调整，默认 340px，1080px 以下自动单栏）或页面自己的网格（用 `gap`，并写 `align-items: start` 或保持等高）。
- 分区标题 + 内容用 `.section-block` 包起来：`sectionHeading(...)` + 卡片网格 / 面板。**并排的每一栏结构要一致**——一栏以分区标题开头，另一栏也要以分区标题开头，这样栏顶天然对齐。不要一栏是“标题 + 卡片”、另一栏是“带标题的面板”。
- 容器内还需要纵向堆叠时用 `.stack`。
- **禁止**用相邻选择器（`.panel + .panel`、`.x + section`）给区块加外边距：它在网格里会把第二栏整体往下推，这正是之前成员页、工作台、项目概览栏顶错位的原因。

### 5.2 列表页

```text
panel
├── .table-toolbar   左：筛选下拉 + switchToggle('archive-filter', '查看归档')   右：计数 + segmented()
├── .table-wrap > table.data-table
│     第一列 .title-cell：item-title 按钮 + .item-meta（<code>编号</code> · 来源）
│     人员列：person(id)    状态列：badge(status)    数字列：.num-cell    最后一列：.action-cell 文字按钮
└── .table-footer    分页（每页 25 条）
```

看板页使用 `.board > .board-column[data-stage] > .task-card`，列头显示 `badge(stage)` 和数量。

项目目录提供「卡片 / 列表」切换，默认保留卡片；显示偏好按账号保存在当前浏览器，不写入业务数据。两种显示共用可访问项目、全文搜索、归档筛选和任务统计，切换保留当前筛选与原项目顺序。列表由 `project-directory.js` 渲染，用于对照负责人、角色、目标日期、工作量和任务完成率；不加入单项目明细或额外编辑操作。完成率仍排除已终止任务，无有效任务时显示「暂无任务」或「任务均已终止」，不显示虚构百分比。手机上卡片单列，表格仅在容器内部横向滚动。目录显示偏好不改变团队工作台的布局。

560px 及以下，项目目录卡片的项目名、负责人和角色自然换行，不用省略号隐藏长项目名；目标日期保留完整年月日且不拆开。卡片「进入项目」、列表进入入口、卡片 / 列表切换及归档开关至少保留 44px 点击高度。项目概览沿用原页头、指标和面板顺序，长项目名、说明、近期交付任务标题及长里程碑在各自区域内换行；近期交付的人员与日期可分行，日期不截断，详情箭头始终可见。项目目录及研发任务的表格继续在容器内横向滚动，手机显示滚动提示，不用缩小文字或隐藏日期列换取整表塞入屏幕；表格容器可聚焦，滚动后仍能进入原项目或任务详情。这些调整仅影响手机阅读与触摸范围，桌面布局、显示切换、统计和角色权限保持原逻辑。

团队工作台由 `workbench-model.js` 只读汇总、`workbench-ui.js` 渲染。四指标固定为「项目目标已过 / 逾期任务 / 未来 7 天到期 / 待我处理」，仅统计可访问且未归档项目：目标已过要求目标日期早于今天且仍有未完成事项；任务逾期排除完成、终止和归档任务；未来七天包括今天至第六天，日期范围明确显示。个人待办按角色与业务责任筛选，同一实体只计一次；读取中或失败显示「—」，不能假装为零。待激活账号仅向管理员提示，不计入个人待办。

工作台欢迎区及四指标在 560px 及以下使用手机紧凑布局：欢迎区收紧内边距与文字间距，保留完整问候、日期、风险说明和小星的破边构图，不固定高度或截断长姓名。指标仍为两列两行，标签与数字并排、隐藏装饰图标，完整统计说明另起一行自然换行；说明至少使用 `--text-sm`（12.5px），日期各自保持完整，日期范围可在两个日期之间换行。多位数字允许标签增加行数，不省略数字或说明。此变体只减少顶部展示留白，不缩小待办字号或触摸入口，不改变统计口径、数据与权限；桌面保留原欢迎区及四指标的排版。样式指南同时保留默认指标条和包含多位数字、跨月完整日期的手机紧凑样例，验收 320px、375px、430px 窄屏。

工作台主栏用「项目推进」摘要取代目录式项目名片，默认突出最多两项主要关注标签与下一步操作，其余关注通过原风险抽屉展开；有效任务完成数量与需求数量始终可见。完整需求阶段、任务状态分布和计划节点收进原生「进展与计划」折叠区，保留完整排期入口；不改变项目排序，不新增健康分或虚构里程碑完成状态。风险详情与准备入口复用已有抽屉及项目任务组，文字按权限使用「查看」或「完善」，不能因系统管理员身份把所有团队风险算为个人任务。首页搜索仅筛选主栏项目推进区，四指标及侧栏仍按完整可访问范围汇总。

560px 及以下手机保留欢迎区与四指标，其后的阅读顺序固定为「待我处理 → 项目推进 → 近期计划节点 → 管理员账号提示」；近期计划节点按原数据条件展示，账号提示仍仅向管理员展示。零待办、读取中和读取失败仍保留个人待办的位置，不按待办数量、读取结果或角色切换布局。首次渲染及手机断点切换时，仅移动同一个个人待办区块，使页面结构和焦点顺序与可见顺序一致；不复制待办、不重新统计，切换时保留当前焦点及折叠状态。超过手机断点后恢复原主栏与侧栏顺序；桌面保留左侧项目推进、右侧个人待办与计划节点，以及原侧栏吸附行为。样式指南的每个工作台样例均使用同一顺序同步函数，首次渲染及断点切换即时更新。

右侧最多展示五项个人待办，桌面首页标题最多显示两行，560px 以下手机放宽至三行，页面结构保留完整文字；完整待办抽屉和详情不截断标题。项目名、截止日期和处理原因分别组织，手机上项目名与日期分行，日期数字不拆开；日期和原因至少使用 `--text-sm`（12.5px）与 `--text-2`，避免为紧凑牺牲阅读。首页标题、「查看全部」和完整清单标题使用文字按钮的 `size: 'touch'`（触摸尺寸），手机点击高度至少 44px、字号使用 `--text-base`（13.5px）。超过五项用只读抽屉列出同一统计口径下的全部事项，并保留原「我的工作」及「站内提醒」入口；零待办用标准空状态的紧凑变体。侧栏独立展示「近期计划节点」：复用各项目下一节点，取今天至第六天、按日期排序、最多三条；其余节点可进入全局排期查看，没有节点则不显示该面板。仅当待办已成功读取且有效事项超过五项时，该面板使用原生折叠区默认收起，摘要显示符合范围的各项目下一节点数量及最近日期；展开后保留原三条节点与全局排期入口。五项及以下、读取中和失败时保持原来的节点展示方式。计划日期不代表完成，不计入个人待办；账号激活提示仍为单独的管理员提示。页内不新增搜索框、完整甘特图或第二套项目详情导航。样式指南保留少量及零待办样例，并提供跨项目十二项待办、长标题和长项目名样例，检查手机三行标题、独立日期、触摸入口和节点展开效果。

研发任务默认按需求分组，由 `task-groups.js` 的 `renderRequirementTaskGroups()` 生成。每组展示需求标题、当前阶段、主责和有效任务完成数；展开后显示任务汇总的研发周期、独立保留的承诺交付日期、可折叠的背景与验收标准，以及任务卡片。任务日期超过承诺时，用带文字的风险标签说明预计延期，不覆盖承诺日期。每组仅新建任务为主操作，研发设置使用次要入口，批量拆分收进更多菜单。默认优先展开尚未拆分的前两项需求；无任务的确认需求保留，归档和早期提议的已有任务可查看但不提供新增入口。筛选只影响任务展示，进度与排期始终用完整任务集合计算。组展开状态通过 `summary[data-task-group]` 交给页面保存。

手机研发任务保留按需求、看板和列表三种视图。需求组标题完整换行，任务完成数量移至标题下方；任务标题和关联需求名允许连续英文名称在内容区域内断行，完整详情不限制标题行数。研发周期与承诺日期分区纵向排列，使用 `<time>`（日期元素）分别保留完整年月日，允许在两个日期之间换行，不能拆开单个日期。任务卡片截止日期使用完整年月日，人员与日期可换行排列；需求、任务详情入口、状态选择、验收操作、背景折叠、更多菜单、研发设置和新建任务在手机上至少保留 44px 点击高度。桌面仍使用原需求组与卡片排列，角色允许的操作和任务流转条件由原业务规则决定；样式指南复用真实需求组和项目列表函数，保留长中英文标题、跨月日期和手机触摸按钮样例。


需求入口分为「需求提议」和「需求池」。提议列表仅标题提供详情入口，评估与采纳操作集中在详情中；确认采纳后保留提议记录并关联已确认需求。需求详情用 `requirements-ui.js` 的 `renderDeliveryWorkflow()` 展示完整交付阶段、下一步及缺项，条件统一读取 `workflow.js`，不要在模板复制业务规则。缺项按当前动作展示：拆分阶段使用主责、负责人和工时等准备条件，排期阶段使用任务起止日期与开工条件，测试阶段只使用最终验收条件，避免把历史开工缺项误写成验收阻碍。阶段条仅突出当前阶段，不将前面的节点伪装成历史验收记录；手机端按三列换行。需求确认后直接根据任务信息和进度同步执行阶段，不设置提交计划或启用按钮；最终验收仍由人工确认。

560px 及以下，需求池保持原表格、筛选和分页骨架，长中英文标题在第一列自然换行，表格只在自身容器内横向滚动；显示滚动提示并允许聚焦表格区域，不缩小文字或隐藏日期列。新建、详情、编辑、筛选、归档和分页操作至少保留 44px 点击高度。原状态、研发周期、承诺日期、点数和角色可用操作均按现有数据与规则显示。

需求详情保留原抽屉、字段和区块顺序。长标题、来源、背景、验收标准、关联任务名及文档和附件文件名在各自区域内完整换行；单个年月日用 `<time>`（日期元素）保持完整，两个日期之间允许换行。关联任务、关联文档、附件和页脚操作，以及关闭与更多入口，在手机上保持至少 44px 点击范围。关联文档阅读器的长弹窗标题自然换行，返回需求和关闭入口保持清楚可触达；需求编辑表单保留原字段，关闭及页脚操作同样保持至少 44px 点击范围。历史基线调用 `review-ui.js` 的 `renderBaseline(requirement, { mobileReadable: true })`，在需求详情与编辑表单提供手机横滑提示与可聚焦表格区域，表格最小宽度 460px，完整比较原始基线、当前承诺与偏移；省略 `mobileReadable`（手机阅读）时保留默认输出。显示优化不改基线捕获、改期次数、历史记录或权限。

交付排期继续复用 `timeline.js` 的 `renderTimeline()`，保留原控件、四指标、甘特图和完整排期列表顺序。手机上缩放、日期定位、筛选和任务标题入口至少保留 44px 点击高度；日期输入及范围使用完整年月日，统计说明完整换行。图中左侧任务名称与完整列表的长标题允许连续英文名称断行，完整列表的首列保持 240px 宽，表格在容器内横向滚动且可聚焦，日期不拆断；没有完整起止日期的任务仍留在完整列表，不从统计范围移除。长里程碑在手机上可展开「里程碑明细」阅读名称和日期，默认收起，桌面不显示该补充区；甘特图中的原节点、缩放及拖动逻辑保持原样。原「批量调整承诺」表单的长需求名在字段组标题中自然换行，不撑宽弹窗；日期、预览、关闭及页脚操作保留完整内容与至少 44px 点击范围。样式指南复用真实交付流程、基线和排期函数，保留长中英文标题、跨月日期、长里程碑与未排期任务样例，默认组件样例同时保留。

提议与需求池表示同一内容在确认前后的阶段，共用 `requirementContentFields()`：标题、优先级、来源、背景与目标、验收标准和关联文档使用相同顺序与说明；确认时背景和验收必填，提议阶段可先补充部分内容。提议另保留提出人及评估字段，交付和协作信息不混入核心内容。文档关联选择器由 `document-link-fields.js` 生成，整体默认折叠并显示已保存关联数，每份文档明确选择“不关联 / 全文 / 指定章节”；指定章节至少选择一项，不以全文覆盖章节的隐式规则决定结果。表单中只做选择，文档预览在详情中打开，避免丢失未保存输入。全文引用保留空章节列表；当前版本缺失的历史章节默认选中，未上传文档引用与独立旧验收用例编号保留。没有选择器标记的提交不清空关联。

项目文档按未归档的关联内容自动显示“已确认 / 未确认 / 未关联”标签与筛选，同一文档可同时关联已确认需求和未确认提议；已转需求的提议不重复计数。提议文档详情保留真实评估状态，阅读器可返回原提议或需求。全文引用显示“全文参考”，不伪装为逐章覆盖；验收用例的精确章节编号与历史验收编号共同解析。

560px 及以下，项目文档保留主文档卡片、分类和表格骨架。长标题与文件名自然换行，更新日期完整显示；表格仅在容器内横向滚动，提供滚动提示，标题仍可直接进入阅读器。上传、分类、阅读和下载入口至少保留 44px 点击高度。分类、关联数量和章节覆盖继续使用原关联规则，全文参考与已转需求提议的统计方式保持不变。

文档阅读器保留原元信息、关联内容、章节大纲和正文顺序；手机上长标题、文件名、章节、版本说明和连续英文正文在各自区域内换行，单个年月日不拆断。章节、关联内容、版本、下载、关闭和返回入口至少保留 44px 点击高度。版本列表在手机上将原操作组移至版本说明下方；查看历史版本继续携带 `fromProposal`（来源提议）或 `fromRequirement`（来源需求）上下文，阅读后仍可返回原详情，不改变版本内容、下载版本或写入权限。

需求提议保留原表格、筛选、分页及详情抽屉。手机长标题、来源、背景、验收标准、评估说明和关联文档自然换行，日期保留完整年月日；表格在自身容器内横向滚动并提供提示。新建、标题、筛选、归档、分页、关联文档、关闭与页脚入口至少保留 44px 点击高度；编辑表单的文档选择器同样保留触摸范围。普通提出人仍只补充本人待评估或待补充提议，评估与采纳仍由产品经理或管理员执行，观察者仍只读。样式指南复用真实文档页、阅读器、版本列表和提议函数，包含长中英文标题、文件名、章节、备注、跨月日期与两种返回上下文，不另建展示布局。

手机端提议与需求的历史记录、上传新版本表单中的长文件名说明完整换行，文件选择控件限制在表单宽度内；只调整显示，不改变历史记录、上传内容或业务规则。

「我的工作」把拆分准备和任务排期缺项合并为「待我安排的需求」，操作入口直接定位研发任务中的对应需求组。全局排期主条优先采用有效任务汇总的研发区间，当前承诺区间独立显示；历史需求缺少任务日期时，备用区间明确标注为历史承诺。历史基线仅在需求详情、编辑和变更记录中保留，不在全局排期显示，也不参与时间范围、逾期或风险计算。风险文案区分任务逾期、承诺逾期、交付逾期和预计延期。实际逾期仅比较今天与未完成事项的截止日期；未来日期晚于承诺或目标仅显示预计延期。已完成和已终止需求不再显示执行延期预测。

### 5.3 弹窗：`openDialog(title, bodyHtml, footerHtml = '', variant = 'drawer')`

| variant | 用途 | 内容结构 |
| --- | --- | --- |
| `drawer`（默认） | 实体详情、新建、编辑、批量操作 | 详情：`.detail-hero`（编号 · 项目 / 标题 / 标签）→ `detailList` → `.detail-section` 分节；表单：`form#entity-form > .dialog-body > .form-grid` + `.dialog-footer` |
| `center` | 二次确认、账号信息、一次性链接、密码修改 | 一段说明文字 + 「取消 / 确认」 |
| `wide` | 文档、原型预览，版本对照 | 预览内容 + 「关闭 / 下载」 |

- 破坏性操作（归档、移出、重置）必须经过 `confirmAction()`（居中弹窗），确认按钮文案写明动作。
- 表单底部：左侧放归档等危险文字按钮，右侧 `.footer-buttons` 放「取消 / 保存」。
- 表单字段 id 统一 `field-<name>`，用 `field()/input()/select()/area()` 生成；必填在标签后拼接 `REQUIRED`。

### 5.4 状态与反馈

| 场景 | 做法 |
| --- | --- |
| 操作成功 | `toast('修改已保存。')` |
| 页面级失败 / 版本冲突 | `presentError(error)` → `#page-alert` 中的 `.notice-danger`，提供「重新载入」 |
| 表单校验失败 | `presentError(error, $('#form-error'))`，错误出现在表单顶部 |
| 数据为空 | `empty(为什么为空, 下一步做什么, action, 按钮文案)`，有权限时才给按钮 |
| 异步读取中 | `loading()`；按钮提交中用 `busy(button, true)`，自动显示转圈 |
| 权限受限 | 页头下方 `readonly()` 说明；不可编辑字段 `disabled`，不要隐藏数据 |

侧栏等空间有限的区域可传 `empty(标题, 说明, '', '', { compact: true })`，使用 `empty-state-compact` 紧凑变体，保持字号、隐藏装饰图标。默认空状态样式不变，不能通过页面样式覆盖通用空状态。

### 5.5 夜色区域

只有三处：侧栏、登录页左侧、团队工作台横幅 `.hero`。**新页面不要新增夜色区域**，也不要在普通面板里使用 `--night-*` 令牌。

| `metric(label, value, note, glyph, tone, alert, { keepDates })` + `metricStrip([...], { mobileCompact })` | `.metrics-grid` | 关键数字，最多 4 个；tone：purple / blue / green / amber。`mobileCompact`（手机紧凑）可选，560px 以下标签与数字并排、说明完整换行；`keepDates`（日期完整）可选，将说明里的每个日期分别保持完整，范围允许换行。默认参数保持原指标条样式 |

## 7. 文案

- 中文界面，句末用中文标点；数字与单位之间空一格：`29 项`、`40 小时`、`共 102 天`。
- 按钮用「动词 + 对象」：新建需求、批量拆分任务、移出项目。不要写「确定」「提交」这类泛化文案（居中确认弹窗除外）。
- 空状态分两句：第一句说明现状，第二句给出下一步。
- 状态词以 `workflow.js` 为准，不要自造同义词（例如不要把「开发中」写成「进行中」）。
- 日期统一 `YYYY-MM-DD`；日期范围用 ` — `。

## 8. 响应式、深色模式与可访问性

- 断点：1240px（双栏变单栏）、1080px（指标条两列、登录页上下排列）、900px（侧栏收起为抽屉、表单单列）、560px（手机）。新页面在 375px 宽度下不能出现横向滚动（表格和甘特图容器内滚动除外）。
- 页面样式必须在浅色和深色下都检查一遍，样式指南右上角可切换主题。
- 所有可点击元素使用 `<button>` 或 `<a>`，图标按钮必须有 `aria-label`；焦点样式由 base 统一提供，不要去掉 outline。
- 颜色不是唯一信息：状态标签带文字，逾期同时显示「已逾期」文字。

## 9. 新增页面 / 模块步骤

1. 在 `/design-system.html` 找到最接近的现有模式和组件。
2. 在 `app.js`（或新建视图模块）里用 `heading` + `panel` + ui-kit 组件实现视图，注册路由与导航。
3. 只有现有组件无法满足时：
   - 可复用的新组件 → 在 `ui-kit.js` 加生成函数，在 `components.css` 加样式，在样式指南加样例，在本文件第 6 节登记；
   - 页面专属结构 → 新建 `design/pages/<页面>.css`，**同时**在 `index.html` 和 `design-system.html` 中引入。
4. 新增业务状态 → 在 `STATUS_TONES` 登记色调并更新 4.2 表格。
5. 新增颜色 → 按 4.1 的流程加令牌。
6. 运行 `npm test`（设计守卫测试会检查令牌、类名、内联样式、样式引入和状态色调）。
7. 启动服务，在浅色、深色、1440px 和 375px 下检查新页面，并打开样式指南确认没有影响现有组件。
