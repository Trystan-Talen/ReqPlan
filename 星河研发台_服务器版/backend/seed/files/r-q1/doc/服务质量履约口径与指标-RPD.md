# 服务质量履约口径与指标 · 需求文档（RPD）

| 项 | 内容 |
| --- | --- |
| 需求编号 | r-q1 |
| 所属项目 | API 执行平台 |
| 版本 | v1（评审稿） |
| 作者 | 产品 |
| 变更摘要 | 首次成文。把"履约"从一句话变成可计算、可对账、两端一致的指标口径 |

## 1. 背景

客户问"我这个月到底达标没有"，现在只能靠客服手工翻后台截图，口径全凭谁来回答。管理侧要盯履约风险客户，也没有统一的数。两侧各算各的，一旦对不上，赔付谈判就没法谈。

本需求是服务质量模块的底座：**先定死口径，再做两个看板。** 口径不定死，客户端和管理端一定算不到一起去。

## 2. 目标

给"履约"一个单一、可复算、两侧一致的计算口径，并把结果落成指标。

**衡量口径：客户在客户端看到的履约结果，与管理端同一客户同一周期的结果，逐条一致率 100%。**

## 3. 范围

**包含**

- 履约周期的定义：自然月，按客户签约的所属时区切分。
- 履约指标的集合与各自的计算口径。
- 指标的数据来源：只读本平台自有的请求级遥测与计费数据。
- 一个统一的服务端计算入口，客户端与管理端共用。

**不包含（本期明确不做）**

- 赔付金额的计算与发放。
- 跨平台取数（资源平台的评级结果只作参考展示，不参与履约判定）。
- 客户自定义指标。
- 历史月份的追溯重算。

## 4. 指标口径

| 指标 | 口径 | 达标线 |
| --- | --- | --- |
| 请求成功率 | 成功请求数 ÷ 总请求数，剔除客户侧 4xx | ≥ 99.5% |
| 履约可用率 | 有成功响应的时间片数 ÷ 应服务时间片数 | ≥ 99.0% |
| 首字节时延 P95 | 当月全部成功请求的 P95，单位 ms | ≤ 800ms |
| 工单响应时长 P90 | 受理时刻 → 首次人工响应时刻的 P90，单位小时 | ≤ 4h |

边界约定：

- 平台自身故障引起的失败计入分母，也计入失败。
- 客户主动触发的限流、超配额返回，不计入分母。
- 同一请求重试多次，按一次请求计。

## 5. 约束

履约计算**只读本平台数据**，不跨平台取数。资源平台的评分与排名不进履约口径，避免把评估侧的口径混进对客户的承诺。客户身份、原始请求内容不出平台。

## 6. 交付物

- 口径说明文档（本文件）。
- 服务端统一计算入口，供 r-q2、r-q3 调用。
- 一组口径自测用例，覆盖边界约定中的每一条。

## 7. 验收标准

1. 对同一客户、同一月份，客户端与管理端返回的每个指标值完全相等。
2. 边界约定的三条规则各有至少一个用例覆盖，并在文档中可追溯到实现位置。
3. 计算过程不产生任何跨平台调用。
