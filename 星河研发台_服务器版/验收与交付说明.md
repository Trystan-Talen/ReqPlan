## 本次修正

| 问题 | 实际改动 |
| --- | --- |
| 项目切换器放在功能下面，控制范围不清楚 | 团队入口独立；“当前项目”选择器放到项目功能之前，项目名称同时出现在选择器、面包屑和页面标题中 |
| 单文件页面不能作为团队服务器应用 | 前端静态文件、接口服务、数据库分别负责展示、业务处理、持久化；前后端独立进程和容器 |
| 原账号明文密码、会话只在内存 | 加盐密码派生、数据库会话、一次性激活与重置、停用撤销、强制改密及终端救援 |
| 缺少项目权限 | 系统管理员与五种项目角色；校验每个请求的所属项目，开发不能修改别人的任务，测试可验收测试阶段的工作 |
| 修改可能互相覆盖 | 数据库事务和记录版本校验；过期版本返回冲突，不覆盖新内容 |
| 真实项目与附件被替换 | 从原完整系统重新保留业务数据；迁移预检、原始编号、附件字节核对和非空库保护 |

团队工作台汇总当前账号有权访问的项目；进入某项目后，需求、任务、排期和成员只属于这个项目。账号管理属于团队层级，不随项目切换改变范围。

- 当前环境禁止监听本地端口，实际网络请求传输和浏览器联调未完成；没有通过换地址或其他方式绕过限制。
- 当前环境没有容器运行环境，镜像构建、容器启动、生产版本运行时与加密入口未验证。
- 没有服务器地址、真实域名和证书配置，本次没有执行远程部署。
- 数据库按单实例内部团队使用设计，尚未进行容量与高并发写入测试。原生数据库接口在目标运行环境仍处于候选发布等级；上线前需固定并验证实际版本，不能把本机测试当作生产认证。
- 账号按管理员开通的内部团队模式实现；没有公开注册、自动邮件发送或外部单点登录。
- 原模型自动分析接口尚未接入。旧页面浏览器内的额外本地编辑也不会自动合并到服务器，需要单独核对迁移。

## 本机查看入口

新增根目录 `启动星河研发台.command`（双击启动文件）：自动选择空闲端口并打开浏览器，首次在网页设置管理员账号和至少 6 位密码；以后沿用现有数据库和账号。当前沙箱仍禁止监听端口，此入口须由用户在本机访达中双击启动，不代表代理已成功启动或完成浏览器验收。

## 已有管理员密码恢复

新增 `重置管理员密码.command`（密码恢复入口）：保持现有服务运行，双击后核对实际服务实例，生成 30 分钟一次性恢复链接，用户在网页设置新密码后登录。签发时撤销该管理员旧密码和会话，保留原账号编号、角色、关联及真实项目。普通登录页已增加“忘记管理员密码？”操作说明。

本次未替用户设置新密码或签发真实恢复令牌；浏览器工具拒绝访问用户运行中的本机地址，恢复页面未完成真实浏览器验收。恢复逻辑已在临时数据库与实际接口处理器中通过测试。用户可在本机双击恢复入口完成密码设置，无需重新初始化项目。

## 管理员登录账号更名

已按用户要求，将本机现有管理员登录账号由 `manager`（原登录账号）更名为 `admin`（当前登录账号）。原人员编号、姓名、密码状态、角色、项目关联、会话和有效恢复链接保持不变；在同一事务中逐表核对了项目、需求、任务、附件及关联数据。原始迁移快照不改名；新环境首次初始化以页面填写的账号为准。
