# 改版方案：角色、流转、PRD 与全局排期

状态：第 1 阶段（角色、权限与流转）已开发，待执行数据库迁移；第 2–4 阶段未开始 · 日期：2026-09-17

## 一、要解决的问题

1. 角色粒度不够：项目经理一个角色同时承担管理、录需求、派任务、验收；没有主开发。
2. 管理者看不到全局：只能进单个项目看排期，没有跨项目的全景和甘特图。
3. 需求没有 PRD 与原型的归宿：附件只挂在单条需求上，HTML 原型不能交互预览，上限 2MB。
4. 任务来源不清：产品和开发都能建任务，没有"需求确定后交给主开发拆分派发"这一步。

团队现状：3 名全栈开发，其中周可担任主开发并负责分发任务；团队不使用迭代/版本概念，按项目管理。

## 二、角色与权限

角色分两层。系统层决定"能看哪些项目、能不能管系统"，项目层决定"在项目里能做什么"。

### 系统层（可叠加）

| 身份 | 说明 |
| --- | --- |
| 系统管理员 | 账号、备份、操作记录、创建项目。现有能力不变。 |
| 管理层 | **只读**查看全部项目（无需加入项目）：项目全景、全局甘特图、报表、需求/任务/文档详情。不参与任何审批或编辑。 |
| 普通成员 | 只能看到自己加入的项目。 |

### 项目层（每个项目一个角色）

| 角色 | 职责 |
| --- | --- |
| 产品经理 | 上传 PRD/原型、录入和维护需求、组织评审、终止需求、确认排期 |
| 主开发 | 领取已确定的需求、拆任务、指定主责开发和任务负责人、估时、排期、验收技术类任务 |
| 开发 | 执行自己负责的任务；可在自己参与的需求下补充任务（负责人只能是自己，主开发会收到提醒） |
| 测试 | 提测验收、登记和验证缺陷、确认需求完成 |
| 观察者 | 只读 |

项目负责人（`ownerId`）必须是该项目的产品经理或主开发，负责管理项目成员（原先由项目经理负责）。

| 操作 | 产品经理 | 主开发 | 开发 | 测试 | 管理层 |
| --- | :-: | :-: | :-: | :-: | :-: |
| 上传/更新 PRD、原型 | ✓ | 仅技术方案 | | | |
| 新建/编辑需求内容 | ✓ | | | | |
| 需求评审流转（未确定↔待评审→已确定） | ✓ | | | | |
| 拆任务、指定主责开发、派任务、改他人任务 | | ✓ | | | |
| 在参与的需求下给自己补任务 | | ✓ | ✓ | | |
| 确认排期（→ 已排期） | ✓ | ✓ | | | |
| 开始开发、提测（任务和需求） | | ✓ | 本人 | | |
| 任务验收完成 | | ✓ | | ✓ | |
| 登记缺陷 | ✓ | ✓ | | ✓ | |
| 需求验收完成 | | | | ✓ | |
| 终止需求 / 终止任务 | ✓ / | / ✓ | | | |
| 管理项目成员 | 负责人 | 负责人 | | | |
| 查看 | 本项目 | 本项目 | 本项目 | 本项目 | 全部项目 |

与现在相比，产品经理**不再**创建和指派任务，任务完全由主开发（及开发本人补充）产生。

## 三、需求与任务流转

```
产品经理：上传 PRD → 录入需求（关联 PRD）
   ↓ 提交评审（需填写背景与目标）
产品经理 + 主开发 + 测试 线下/线上评审 → 已确定（需填写验收标准）
   ↓ 自动进入主开发的「待拆分」列表
主开发：拆任务、指定主责开发和每个任务负责人、估时 → 待排期
   ↓
产品经理或主开发：填写计划起止日期 → 已排期（首次排期记录基线）
   ↓
开发：开始开发（前置需求须已完成）→ 所有未终止任务提测后 → 测试中
   ↓
测试：验证；有问题登记缺陷并打回开发中 → 缺陷全部关闭且任务全部完成 → 已完成
```

### 需求状态流转规则

| 流转 | 执行角色 | 条件 |
| --- | --- | --- |
| 未确定 → 待评审 | 产品经理 | 已填写背景与目标 |
| 待评审 → 未确定 / 已确定 | 产品经理 | 已确定需填写验收标准 |
| 已确定 → 待排期 | 主开发 | 已指定主责开发，至少一个任务，每个任务有负责人和工时 |
| 待排期 / 已确定 → 已排期 | 产品经理、主开发 | 满足上一条，并填写计划起止日期 |
| 已排期 → 已确定（退回） | 产品经理、主开发 | — |
| 已排期 → 开发中 | 主开发、开发 | 前置需求已完成 |
| 开发中 → 测试中 | 主开发、开发 | 所有未终止任务处于测试中或已完成 |
| 测试中 → 开发中（打回） | 测试 | 填写原因或存在未关闭缺陷 |
| 测试中 → 已完成 | 测试 | 任务全部完成或终止，缺陷全部关闭或标记不修复 |
| 已完成 → 开发中（重开） | 产品经理、测试 | 填写原因 |
| 任意 → 已终止 | 产品经理 | 填写原因 |
| 已终止 → 未确定 | 产品经理 | — |

### 任务规则

- 新任务必须关联需求（现有数据中没有未关联的任务）。
- 任务状态：待开始 → 开发中 → 测试中 → 已完成；负责人本人或主开发推进到测试中；测试或主开发确认完成（纯技术任务无法测试时由主开发确认）。
- 终止任务由主开发执行并填写原因。
- 开发补充的任务在主开发的站内提醒里出现，主开发可调整或终止。

## 四、缺陷（轻量）

| 字段 | 说明 |
| --- | --- |
| 标题、复现步骤 | 必填 |
| 严重程度 | 致命 / 严重 / 一般 / 轻微 |
| 关联 | 必须关联需求，可选关联任务 |
| 处理人 | 默认取关联任务负责人，否则取需求主责开发 |
| 状态 | 待处理 → 修复中 → 待验证 → 已关闭；待验证可重新打开为修复中；产品经理可标记"不修复"（需原因） |

- 测试、产品经理、主开发可以登记；处理人推进到待验证；测试验证后关闭或重新打开。
- 需求完成前，其缺陷必须全部为"已关闭"或"不修复"。
- 缺陷显示在需求详情、个人工作台（处理人）、项目全景（未关闭数）中。

## 五、PRD 与原型

### 项目文档

新增"项目文档"，挂在项目下，不再只挂单条需求：

- 类型：PRD、原型、技术方案、其他。
- 一份文档可关联多条需求，需求详情里显示它关联的文档；文档详情里显示它覆盖的需求。
- 同一文档上传新文件形成新版本，保留全部历史版本，文本类文件可对比差异。
- 新版本上传后，提醒关联需求（未完成的）的主责开发、主开发和测试。
- 上传权限：产品经理（全部类型）、主开发（技术方案）。

### 格式与预览

| 格式 | 处理 |
| --- | --- |
| `.md` `.txt` | 页面内渲染预览（沿用现有文档预览） |
| `.html` 单文件原型 | 隔离框内**可交互**预览，可新窗口打开 |
| `.pdf` | 浏览器内预览 |
| `.docx` `.xlsx` 等 | 仅下载 |

- 单文件上限提高到 20MB。多文件原型（压缩包）放到后续。
- 安全：HTML 原型通过单独地址返回，响应头 `Content-Security-Policy: sandbox allow-scripts allow-popups`，框架使用 `sandbox="allow-scripts"` 且不带 `allow-same-origin`。原型脚本处于无来源的隔离环境，读不到登录状态，会话 Cookie（`SameSite=Strict`）不会随它发出的请求携带，因此无法以当前用户身份调用接口。`deploy/nginx.conf` 目前全局禁止被嵌入（`frame-ancestors 'none'`），需为该预览地址单独放行为 `'self'`。
- 存储沿用数据库内保存。文档和历史版本会增大数据库和备份体积，累计超过约 1GB 时再迁移到文件存储。

### 现有附件

现有需求附件（2 份）原样保留在原需求上，下载地址不变；需求详情提供"转为项目文档"操作，由人工决定是否转移，不自动迁移。

## 六、项目全景与全局甘特图

### 可见范围

- 系统管理员、管理层：全部未归档项目。
- 其他成员：只显示自己参与的项目。
- 全部只读，点击条目在右侧抽屉显示详情，可跳转到对应项目。

### 项目全景（表格）

每个项目一行：负责人、当前里程碑与目标日期剩余天数、需求各状态数量（分段条）与完成率、延期状态与天数、逾期任务数、未关闭缺陷数、待评审/待拆分/待排期积压数。

### 全局甘特图

**按项目视图**（默认）：项目 → 需求 → 任务三级，可逐级展开，默认只展开到项目层。

| 元素 | 规则 |
| --- | --- |
| 需求条 | 计划开始 → 计划结束；条下细线为基线（首次排期日期） |
| 需求进度 | 已完成任务工时 ÷ 未终止任务总工时；无工时时按任务个数 |
| 项目条 | 由需求自动计算：最早计划开始 → 最晚计划结束；进度按工时汇总 |
| 项目目标日期 | 竖向参考线；里程碑以菱形标出 |
| 未排期需求 | 不画条，项目行显示"待排期 N 条" |
| 今天 | 竖线 |

**状态判定**（需求级，项目取其需求中最差的状态）：

- 已延期：需求未完成，且今天已超过计划结束日，或计划结束日晚于基线结束日。延期天数取两者中较大者。项目另外判断：最晚需求结束日晚于项目目标日期也算延期。
- 有风险：未延期，且满足任一条件——已过时间比例比进度高出 20 个百分点以上；有未关闭的致命或严重缺陷；前置需求未完成而今天已到计划开始日。
- 正常：其余情况。

**按人员视图**：每人一行，显示其在所有可见项目中负责的未完成任务，条上标注项目名，用于发现同一时段多项目并行的负载冲突。

**筛选与时间范围**：项目、负责人、只看延期/有风险；时间范围沿用周 / 月 / 季度 / 全周期与缩放。

实现上复用 `frontend/timeline.js` 中与项目无关的日期、刻度、缩放函数，新写多项目的范围计算与分层行渲染；页面样式按 DESIGN.md 新建 `design/pages/portfolio.css`。

现有数据可直接支撑：56 条未归档需求中 52 条已有计划日期。

每个阶段独立交付：运行 `npm test`，在浅色/深色主题、1440px/375px 宽度下检查改动页面，并核对真实数据未被改变。

4. **缺陷**：缺陷记录与流转、需求完成条件、工作台与全景接入。
