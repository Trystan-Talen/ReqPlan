## 2026-10-10：性能优化与线上数据兼容复核

**本轮性能优化未新增数据库迁移或改变接口字段，可以进入发布验收；当前整个工作区不能直接作为“仅性能优化”的更新包放行。** 本轮没有部署、连接线上数据库或执行真实数据迁移。

### 本轮改动范围

- [实体查询](backend/business.mjs)：过滤提前到数据库，可见项目、归档范围、排序、编号、版本和返回字段保持原规则。
- [工作台汇总](backend/work-service.mjs)：在同一次读取中复用分组与计算结果；提醒标识和已读关联保留，不使用跨请求缓存。
- [页面刷新与编辑](frontend/app.js)、[全局排期](frontend/portfolio.js)：仅计算可见视图，防止旧刷新覆盖新会话/新结果。通用编辑表单固定打开时的记录版本，避免在途刷新替换全局数据后，旧表单冒用最新版本覆盖其他人的修改。
- [接口镜像文件](deploy/api.Dockerfile)：补入已有共享模块，不改数据库路径、数据卷或启动命令。
- 对应测试、隔离浏览器验收工具与持续集成检查。发布必须包含所选改动依赖的新文件，不能只加入已跟踪文件。

### 数据兼容性证据与限制

使用随包脱敏历史数据在临时文件数据库中，与本地修改前代码进行了 56 组初始化结果和 42 组工作台汇总对照，结果完全一致；全部原始表内容和数据库结构未变化，关闭重开后，修改前后的读取代码均能读取相同数据。该基线包含 3 个项目、55 条需求和 79 条任务，**只是测试输入，不能作为线上数据数量或线上版本的证明**。

[持久化兼容测试](backend/tests/performance-contract.test.mjs) 另覆盖历史缺省字段、中文状态、未知扩展字段、原版本、账号、关联、审计、附件字节和文档版本，确保读取后关闭重开仍保持全部原始行与结构。前端回归测试覆盖旧编辑版本冲突；桌面/手机、明暗主题、保存刷新、账号权限和样式指南已在隔离示例库验收。

本轮最终全套 328 项测试通过，无失败或跳过；脚本语法与差异格式检查通过。真实浏览器的两个页面同时编辑示例项目时，新修改保存成功，旧表单提交收到版本冲突；重新读取确认新修改仍保留、旧说明没有写入。更新后浏览器必须重新加载脚本才能获得这项保护，仍开着旧页面的客户端不会自动拥有修复。

尚未取得线上当前版本与数据库快照进行同版本升级演练；本机未安装容器运行工具，实际镜像构建尚未验证。因此上述结果证明代码层面的兼容性，不代表整个线上发布流程已经验收。

### 与本轮优化分开的已有工作区变更

[服务入口](backend/server.mjs) 还有此前未提交的启动校准，会调用 [交付阶段迁移](backend/delivery-migration.mjs)，修改符合条件的旧需求阶段、自动交付标记、版本、更新时间并追加审计。它有事务回滚与重复启动测试，但并非只读优化，回退程序也不会自动撤销这些数据变化。复核时迁移文件尚未加入版本控制：遗漏它会导致服务入口无法加载；整目录打包则会把迁移一起发布。

若本次只发布性能优化，应从确认的线上代码版本组装上列改动，并验证完整候选包，不捎带启动迁移或其他未提交业务变更。若同时发布启动迁移，必须单独审查线上快照副本中的实际变化，不能沿用“数据不改写”的结论。

### 更新真实实例的必要条件

1. 继承线上原有数据库路径、实际数据卷和环境配置。默认数据库路径与代码目录相关，编排卷名也受项目名影响；换目录不等于自动接回原库。
2. 更新前制作并核验完整快照，保留旧程序与原数据位置；不执行首次初始化、随包基线导入或覆盖原库的导入步骤。
3. 在快照副本上启动最终候选版本，核对账号、项目、需求、任务、文档/附件内容与关联、权限及保存冲突，再决定发布。仅检查数据数量不够。
4. 现有恢复检查只覆盖数据库打开和结构升级，尚未执行上述启动阶段校准；启动后的自动备份也不能代替更新前快照。

## 本地验证口径

自动测试使用 Node.js 24.19.0（运行环境），数据库仅使用内存或临时目录。验证覆盖权限、账号与恢复、流程、事务及并发、批量拆分、依赖、附件版本和补录、旧历史、改期、备份与恢复演练。本次全量 182 项测试通过；另有命令行工具 11 项测试通过，47 个脚本语法检查通过。实际本机端口接口测试 3 项通过（属于全量用例的传输复测，不重复计数）。

前端契约测试运行实际界面模块及同一接口处理器，使用简化页面节点；它验证数据和行为，不能代替真实浏览器的布局、键盘操作与移动端检查。实际端口传输与浏览器检查应分别记录。

备份恢复专项验证包括：预写日志数据、并发同名目标、防覆盖、损坏和外键错误、保留策略、第二目录失败、重试、关闭等待、日志脱敏，以及恢复前后源文件不变。旧结构的恢复升级发生在临时副本内。

## 可复现检查

在完整源码目录执行：

```sh
node --version
npm test
XINGHE_HTTP_SOCKET=1 node --test backend/tests/http.test.mjs
```

第三条需要允许监听临时本机端口。测试不调用 `reseed`（重填业务数据脚本），也不会用真实账号密码初始化测试库。

持续集成配置已提供，本轮未执行远程任务，不能宣称远程检查已经通过。现有环境没有 Docker（容器运行工具），容器构建及启动应在隔离验证环境或发布流程中验证；以下不是对运行中真实实例的直接更新指令：

```sh
docker compose config --quiet
docker compose build
docker compose run --rm --no-deps api node --input-type=module -e "await import('./backend/server.mjs'); await import('./frontend/workflow.js'); console.info('后端及共享规则可加载');"
docker compose up -d
docker compose ps
```

接口镜像只包含后端运行文件和共享规则，完整前端与启动器测试应在源码目录执行，不在裁剪后的接口镜像中运行全量测试。

## 目标环境业务验收

| 场景 | 应观察到的结果 |
| --- | --- |
| 管理员与成员登录 | 原账号沿用，六位最低长度、限流和会话过期规则有效 |
| 只读与跨项目访问 | 可读可见项目，写入和越权请求被拒绝 |
| 批量拆分 | 全部成功或全部不写；重试不产生重复任务 |
| 工作流和依赖 | 页面可操作项与接口一致，依赖未完成不能开工 |
| 附件升级和历史 | 旧地址字节不变，新版本、历史来源和文本对照可查看 |
| 改期 | 基线与现计划可比较；批量预览与冲突回滚有效 |
| 个人事项和提醒 | 仅显示有权限事项；已读状态保留，未解决风险仍展示 |
| 统计报表 | 归档、终止、未排期及缺少完成日期按界面口径处理 |
| 服务重启 | 数据、关联、账号与历史仍在 |
| 备份与演练 | 生成新快照，失败可见；恢复校验不替换运行库 |

附件历史补录先在原目录只读预检，并核对未匹配项；正式补录需要明确指定目标数据库，自动备份后才写入。不能凭存在补录脚本宣称原历史已全部导入。
