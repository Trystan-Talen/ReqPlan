## 本地验证口径

自动测试使用 Node.js 24.19.0（运行环境），数据库仅使用内存或临时目录。验证覆盖权限、账号与恢复、流程、事务及并发、批量拆分、依赖、附件版本和补录、旧历史、改期、备份与恢复演练。本次全量 182 项测试通过；另有命令行工具 11 项测试通过，47 个脚本语法检查通过。实际本机端口接口测试 3 项通过（属于全量用例的传输复测，不重复计数）。

前端契约测试运行实际界面模块及同一接口处理器，使用简化页面节点；它验证数据和行为，不能代替真实浏览器的布局、键盘操作与移动端检查。实际端口传输与浏览器检查应分别记录。

备份恢复专项验证包括：预写日志数据、并发同名目标、防覆盖、损坏和外键错误、保留策略、第二目录失败、重试、关闭等待、日志脱敏，以及恢复前后源文件不变。旧结构的恢复升级发生在临时副本内。

## 可复现检查

在完整源码目录执行：

```sh
node --version
npm test
XINGHE_HTTP_SOCKET=1 node --test backend/tests/http.test.mjs
```

第三条需要允许监听临时本机端口。测试不调用 `reseed`（重填业务数据脚本），也不会用真实账号密码初始化测试库。

持续集成配置已提供，当前目录没有连接远程仓库，不能宣称远程任务已经通过。现有环境没有 Docker（容器运行工具），容器构建及启动应在目标服务器验证：

```sh
docker compose config --quiet
docker compose build
docker compose run --rm --no-deps api node --input-type=module -e "await import('./backend/server.mjs'); await import('./frontend/workflow.js'); console.info('后端及共享规则可加载');"
docker compose up -d
docker compose ps
```

接口镜像只包含后端运行文件和共享规则，完整前端与启动器测试应在源码目录执行，不在裁剪后的接口镜像中运行全量测试。

## 目标环境业务验收

| 场景 | 应观察到的结果 |
| --- | --- |
| 管理员与成员登录 | 原账号沿用，六位最低长度、限流和会话过期规则有效 |
| 只读与跨项目访问 | 可读可见项目，写入和越权请求被拒绝 |
| 批量拆分 | 全部成功或全部不写；重试不产生重复任务 |
| 工作流和依赖 | 页面可操作项与接口一致，依赖未完成不能开工 |
| 附件升级和历史 | 旧地址字节不变，新版本、历史来源和文本对照可查看 |
| 改期 | 基线与现计划可比较；批量预览与冲突回滚有效 |
| 个人事项和提醒 | 仅显示有权限事项；已读状态保留，未解决风险仍展示 |
| 统计报表 | 归档、终止、未排期及缺少完成日期按界面口径处理 |
| 服务重启 | 数据、关联、账号与历史仍在 |
| 备份与演练 | 生成新快照，失败可见；恢复校验不替换运行库 |

附件历史补录先在原目录只读预检，并核对未匹配项；正式补录需要明确指定目标数据库，自动备份后才写入。不能凭存在补录脚本宣称原历史已全部导入。

## 交付边界

- 交付的是服务器版源码与维护工具；远程部署、实际域名、证书和容器运行结果另行验收。
- 第二备份目录未配置时只有本地备份；不同目录或不同设备编号不能代替物理异地及恢复证明。
- 尚未完成服务器容量与高并发写入测试。
- 邮件、外部推送、单点登录和自动模型分析未接入；原模型凭证撤销状态仍需所有者核实。
- 原脱敏快照的 3 个项目、55 条需求、79 条任务、6 位人员及 2 份当前附件是迁移基线，不能当作运行库必须回退到的数量。
